The retrieval problem

A question needs a neighborhood, not a pile of chunks.

Naive RAG retrieves text that resembles the question. It has no notion of a symbol, so it cannot tell you who calls a function or what that function calls in return.

CodeOrbit retrieves the subgraph the question actually lives in: the symbol, its source, its callers, and its callees. That neighborhood is what a person reading the code would need, and structure is the only thing that can hand it over.

How it's built

Two passes, not one.

A call can name something defined in a file tree-sitter hasn't reached yet, so nothing is resolved until every definition in the project is known.

1

scanner

Walks the repo, skips vendored and generated files, respects .gitignore, and names any language it had no grammar for.

2

extract

Tree-sitter turns source into symbols, call sites and imports. Hand-written for three languages, table-driven for thirty, inferred for the rest.

3

indexer

Writes nodes and pending calls into SQLite.

4

resolve

Binds call sites to real definitions, ranked by confidence.

5

query

Callers, callees, impact, and the subgraph a question lives in.

6

serve

Answered by a model in Ollama, or handed to any MCP agent over stdio.

Coverage

Most repositories are not one language.

A Rails app has JavaScript in it. A Go service has Terraform beside it. A Flutter app is Dart and Kotlin and Swift at once. A tool that reads three of those reads none of them properly.

Tier 14

Hand-written

Python, JavaScript/JSX, TypeScript/TSX. The languages this is measured on, where a tuned extractor catches what a generic one cannot: PEP 257 docstrings, an arrow function bound to a const, extends B implements C.

Tier 230

Table-driven

A Spec per language saying which node types are definitions, calls and imports. Go methods bind to their receiver; a Rust impl folds into its struct; Elixir gets a hook, because def there is a macro call and the grammar has no definition node at all.

Tier 3103

Inferred

The node types are read out of the grammar itself and classified by name. Tree-sitter grammars converge hard on function_definition, class_declaration, call_expression — so a language nobody here has looked at still yields a graph.

What it does not do

  • A language with no grammar installed is skipped and named, never indexed empty. A file row with no symbols is indistinguishable from an empty file, and that is a lie the graph then repeats to the model.
  • Inference is weaker than a table entry. Nim and Crystal yield symbols and imports but no call edges, because their call nodes are named in ways the patterns do not reach. That limit is pinned by a test rather than papered over.
  • Name resolution never crosses a language family. TypeScript, JavaScript, .vue and .svelte compile together and call each other. Go and Python do not, and binding a Go Load to a Python load produced edges that were pure coincidence.
The command surface

One graph, six ways to use it.

Every command reads the same index, so what search finds, review, audit, and fix already know.

MCP

Serve the graph to Claude Code, Cursor, or any MCP client. It reads real source and call edges, not a guess — and budgets what it returns, so a repeated question costs a fraction of the first.

codeorbit install-mcp --agent claude

Ask

No agent handy? A local model in Ollama answers, grounded in the same graph.

codeorbit ask "How does Console.print render output?"

Explore

Search by name, trace impact, find what nothing calls.

codeorbit impact Segment --depth 2

Review & audit

Changed symbols ranked by blast radius, findings ranked by reach.

codeorbit review --base main

Fix

Proposed fixes verified against syntax, symbol identity, and your tests.

codeorbit fix -s high --apply --test

Visualize

An interactive graph served on loopback, or exported as one self-contained file. Opens on macOS, Windows, Linux and WSL — and says why when it can't.

codeorbit viz --focus Segment

For agents

A tool call has to cost less than the file read it replaces.

That is the whole claim, and the first version did not clear the bar convincingly. Four picks, a flat 120-line body each, clipped at 24,000 characters — about six thousand tokens a call, most of it spent on the pick least likely to be the answer.

Estimates, and they say so: four characters per token is a budgeting ratio, not a tokeniser. The shape is the point — the saving grows the longer the session runs, which is exactly when an agent's context is under pressure.

01

Taper, don't cap

The first pick earns a long body; the fourth earns enough to recognise. The symbol that matters is never the one shortened.

02

Never print the same code twice

Retrieval routinely returns a class and one of its own methods, whose bodies overlap exactly. The second becomes a pointer at the first.

03

Remember what you already sent

A session is explore, then node, then impact, over the same few symbols. After two full sends the body becomes a citation — with detail="full" as the escape hatch, because withholding a body the agent no longer has is worse than re-sending one.

Runs where you run

The viewer opens, or tells you why it can't.

codeorbit viz is the command most likely to run somewhere that is not a laptop. It used to call webbrowser.open and throw the answer away, which failed three ways and reported all three as success.

It blocked

With no graphical browser registered, Python picks a console one and waits for it to exit. That ran before serve_forever() — so the terminal browser took the terminal and the server it pointed at never started answering.

It did nothing

Headless, containerised, or over SSH without X forwarding, the call returns False. Nobody looked at the return value, so nothing was printed and the user waited for a window that was never coming.

It looked in the wrong place

Under WSL it searched inside the VM for a browser that lives on the Windows side, reached through wslview or powershell.exe.

Windowscmd /c start ""

WSLwslview · powershell.exe
Headlessprints the URL and the ssh -L to reach it

Each opener is spawned detached, so nothing can block, and on_ready runs on its own thread so even a slow one cannot delay serving. CODEORBIT_NO_BROWSER=1 turns the attempt off for CI.

Nothing leaves the machine.

CodeOrbit itself never calls out: indexing runs on disk, and the graph is served over local stdio. Answer fully offline with a model in Ollama, or hand the same graph to Claude Code, Cursor, or any agent you already use.
