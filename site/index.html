The retrieval problem

A question needs a neighborhood, not a pile of chunks.

Naive RAG retrieves text that resembles the question. It has no notion of a symbol, so it cannot tell you who calls a function or what that function calls in return.

CodeOrbit retrieves the subgraph the question actually lives in: the symbol, its source, its callers, and its callees. That neighborhood is what a person reading the code would need, and structure is the only thing that can hand it over.

How it's built

Two passes, not one.

A call can name something defined in a file tree-sitter hasn't reached yet, so nothing is resolved until every definition in the project is known.

1

scanner

Walks the repo, skips vendored and generated files, respects .gitignore.

2

extract

Tree-sitter turns source into symbols, call sites, and imports.

3

indexer

Writes nodes and pending calls into SQLite.

4

resolve

Binds call sites to real definitions, ranked by confidence.

5

query

Callers, callees, impact, and the subgraph a question lives in.

6

serve

Answered by a model in Ollama, or handed to any MCP agent over stdio.

The command surface

One graph, six ways to use it.

Every command reads the same index, so what search finds, review, audit, and fix already know.

MCP

Serve the graph to Claude Code, Cursor, or any MCP client. It reads real source and call edges, not a guess.

codeorbit install-mcp --agent claude

Ask

No agent handy? A local model in Ollama answers, grounded in the same graph.

codeorbit ask "How does Console.print render output?"

Explore

Search by name, trace impact, find what nothing calls.

codeorbit impact Segment --depth 2

Review & audit

Changed symbols ranked by blast radius, findings ranked by reach.

codeorbit review --base main

Fix

Proposed fixes verified against syntax, symbol identity, and your tests.

codeorbit fix -s high --apply --test

Visualize

An interactive graph in one HTML file. No server, no network.

codeorbit viz --focus Segment
